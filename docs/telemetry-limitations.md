# Telemetry accuracy and detection limitations

- **AdGuard Home:** The query-log API in this adapter exposes timestamps and query contents but does not guarantee a stable per-request UUID. Phase 6 retains the original hash for the first occurrence and appends an occurrence index to further identical entries within each retrieved ordered snapshot, preserving two identical queries seen in the same poll. Replay identity can still be ambiguous when the query log rotates, entries reorder, or the same timestamp is reused across polls. Do **not** claim exactly-once ingestion. The 5-second overlap and page budget reduce but cannot eliminate gaps.
- **CrowdSec:** The Bouncer API is treated as a changing *current decision snapshot*, not a lossless historical alert feed; short-lived decisions between polls can be missed. Collected decisions do not prove compromise.
- **OPNsense syslog:** TLS authenticates the sender; downstream delivery is buffered and idempotently keyed per reception but end-to-end lossless delivery requires testing source buffering, transport disruptions, Vector crash recovery and a durable journal.
- **Detection:** Live alerts use a 15-minute event-time window and five minutes of future clock tolerance. Events up to 24 hours old can update rollups while older rows remain queryable as evidence. The deployment has no historical rule replay command.
- **LLM:** A valid event ID ensures referential provenance, not semantic correctness of a model conclusion. A human must validate incident claims. Source data can contain malicious prompt-injection text.
- **Response:** Phase 6 has only human-approved *simulated* response. No firewall alias or rule is modified. Actor handles are self-asserted; a future real executor requires identity-backed approvals and time-limited rollback.
